# Evaluation protocol

This protocol is written before any task is run. Changing it after results are seen requires a new version of this file and a note explaining why.

## 1. Benchmark

[τ²-bench](https://github.com/sierra-research/tau2-bench) 2.0, domains airline, retail and telecom. Rewards are 0 or 1 and depend on the final database state and on whether required information was communicated; these three domains do not score the action sequence ([docs/evaluation.md](https://github.com/sierra-research/tau2-bench/blob/main/docs/evaluation.md)).

## 2. Split (frozen, **done**)

`data/splits/tau2-split-v1.json`, generated by `scripts/make_split.py` from the official split files at upstream commit `7aad81c`:

| Part | Source | airline | retail | telecom | Total | Used for |
|---|---|---|---|---|---|---|
| test | official `test` | 20 | 40 | 40 | 100 | the single final run per configuration |
| dev | 20% of official `train`, `random.Random("2026:<domain>")` | 6 | 15 | 15 | 36 | choosing mechanisms, thresholds, hyperparameters |
| distill | rest of official `train` | 24 | 59 | 59 | 142 | collecting fine-tuning trajectories only |

`make_split.py --check` (run in CI) proves the committed file follows these rules. The script refuses to overwrite the file; a change means a new `tau2-split-v2`.

## 3. Sealing the test split (**done**)

- `evals.splits.task_ids(domain, "test")` raises `SealedSplitError` unless `STEADFAST_FINAL=1`.
- Every final run must be recorded with `python -m evals.run_log append --config <name>`. The command refuses to run on a dirty working tree, stores the git commit and the split file hash, and chains each record to the previous one by SHA-256. Commit `results/final_runs.jsonl` right after each append, so the next final run starts from a clean tree. `python -m evals.run_log verify` (run in CI) fails if any earlier record was edited or deleted.
- Nothing is selected by looking at test results.

## 4. Configurations

| Name | Description | Role |
|---|---|---|
| B0 | τ²'s official `llm_agent` | reference |
| B1 | Steadfast loop with no mechanisms, copying `llm_agent`'s prompt and parameters | control for the main comparison |
| F | B1 + mechanisms selected on dev | main result |
| S | same number and shape of calls as F, gate replaced by a generic "check again" prompt | separates the gate's content from the extra compute |
| F−x | F without mechanism x (at most 3) | ablation |
| L, L+G | LangGraph `create_agent` defaults, then with the gate middleware | descriptive |
| Student-base, Student-SFT | Qwen3.5-2B before and after LoRA, run in B1; Student-SFT also with the gate off/on | distillation results |

Agent and teacher model: DeepSeek V4.1-Flash-1017 (API name `deepseek-flash`). User simulator: GLM-5.3-Flash, temperature 0, a different vendor from both agent and student. Every result file records the model version string returned by each API call.

## 5. Endpoints

Pre-registered primary comparisons, test split, paired by task, Holm-corrected at α = 0.05:

1. **Wrong-write rate**, F vs B1: trials with at least one executed write whose final database state is wrong, divided by trials with at least one executed write.
2. **Average success**, F vs B1, and Student-SFT vs Student-base: the share of 3 trials that succeed, averaged over tasks, domains weighted equally. Paired permutation test, 10,000 permutations, with a 95% bootstrap interval.

Reported but not tested: pass^1, pass^3, cost and tokens per solved task, cache hit rate, P50/P95 latency, wrongly-blocked-write rate (strict: the blocked call matches the reference call; behavioral: tasks that pass without the gate and fail with it), false-completion rate, transfer-to-human rate, per-domain results.

Before the final run, dev results (B0 and B1, 3 trials each) are used to estimate the smallest effect this test set can detect. If that effect is larger than what similar mechanisms achieved in the literature, success rate is reported descriptively and the wrong-write rate and cost become the headline.

## 6. Fairness rules

- All configurations in one comparison run interleaved by task inside one 48-hour window. DeepSeek has changed the model behind the same API name three times between July and October 2026, so results from different windows are never mixed.
- Retry and timeout settings are identical across configurations; model fallback is disabled during evaluation. Infrastructure errors are rerun for all configurations.
- Failure analysis uses written labeling rules, labels with configuration names hidden, and reports agreement (κ). Headline numbers include all tasks; results excluding annotation errors are an appendix with the list of excluded tasks.

## 7. Comparability

The user simulator and the communication judge are domestic models, because the official defaults (OpenAI models) cannot be used from mainland China. Scores are therefore comparable within this project only, not with the τ² leaderboard or model cards.
